## Microsoft PBIR validator

The current public package is
[`@microsoft/powerbi-report-authoring-cli` 0.1.4](https://www.npmjs.com/package/%40microsoft/powerbi-report-authoring-cli).
Its executable is `powerbi-report-author`, and the validation command is:

```text
powerbi-report-author validate <path-to-.pbip-or-.Report>
```

The package documents one JSON envelope on stdout: success uses a top-level
`data` field; CLI failure uses a top-level `error` field. Validation reports a
result, error and warning counts, report path, and grouped diagnostics.

The CLI is public preview and explicitly warns that 0.x command/library
surfaces may change, supporting the exact-version pin and frozen-contract tests.

## Validation is not rendering

Microsoft's authoring guidance requires both PBIR validation and Desktop
reload/screenshot review for rendered changes. It explicitly states that page
scaffolding alone is not completion and that each requested page needs bound
visuals. See the official
[`powerbi-report-authoring` guidance](https://github.com/microsoft/skills-for-fabric/blob/main/plugins/powerbi-authoring/skills/powerbi-report-authoring/SKILL.md).

The same project issue tracker documents real reports that passed local CLI
validation but still failed to load in Desktop. See
[`microsoft/skills-for-fabric#37`](https://github.com/microsoft/skills-for-fabric/issues/37).
This is why the application exposes distinct **Validated locally** and
**Desktop render verified** states.

## Strict-offline validator risk

An upstream report documents authoring-validator schema fetches from
`developer.microsoft.com` and a schema-version availability mismatch. See
[`microsoft/skills-for-fabric#55`](https://github.com/microsoft/skills-for-fabric/issues/55).
Therefore real-mode preflight requires verified offline schema availability;
merely having the executable installed is insufficient.

Another open issue reports valid Desktop-authored hierarchy and compact slicer
patterns being flagged as hard errors by validator 0.1.4. See
[`microsoft/skills-for-fabric#60`](https://github.com/microsoft/skills-for-fabric/issues/60).
The default warning/error policy stays fail closed. Any exception would require
a narrow, evidence-backed decision-log entry against the exact Desktop build.
